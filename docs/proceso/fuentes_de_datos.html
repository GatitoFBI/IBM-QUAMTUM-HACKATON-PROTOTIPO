Reporte Técnico de Fuentes de Datos

Hackathon NTT DATA & IBM Quantum: Optimización Cuántica (QAP) aplicada a la Gestión de Riesgos del Fenómeno de El Niño en Perú.

1. Resumen Ejecutivo

Para resolver el Problema de Asignación Cuadrática (QAP) planteado en el reto, es necesario construir dos matrices fundamentales:

  • Matriz de Flujo (\(F_{ik}\)): El nivel de interacción o sinergia entre los elementos (brigadas o recursos) que vamos a asignar.
  • Matriz de Distancia (\(D_{jl}\)): El costo (tiempo o distancia geográfica) de trasladarse entre las ubicaciones (zonas de riesgo o albergues).

Este reporte detalla las plataformas oficiales e internacionales de donde se pueden extraer datos reales y abiertos para construir estas matrices, dotando al proyecto de un rigor operativo y social adaptado a la realidad peruana.

min C(x) = Σ Σ Fik * Djl * xij * xkl

2. Directorio de Plataformas de Datos

2.1. Clima y Meteorología (Riesgo)

Fuente oficial para justificar la vulnerabilidad del terreno y la probabilidad de desastres.

Plataforma Datos Disponibles Uso en el QAP
SENAMHI
senamhi.gob.pe		 Pronósticos, Índice de Crecida del Niño (ICEN), datos históricos de lluvias extremas (1983, 1998, 2017). Identificar las zonas (j, l) con mayor probabilidad de inundación para priorizar su asignación.

2.2. Emergencias y Desastres (Flujo Operativo)

Datos esenciales para calcular la matriz de Flujo (\(F_{ik}\)), determinando qué tipo de ayuda necesita cada zona.

Plataforma Datos Disponibles Uso en el QAP
INDECI
gob.pe/indeci		 Visor de emergencias, estadísticas de damnificados y afectados por departamento/distrito. Determinar la magnitud del flujo (Fik). Un distrito con más damnificados tendrá un flujo mayor de requerimiento logístico.

2.3. Geoespacial y Rutas (Distancias)

Para calcular \(D_{jl}\), no usamos distancia en línea recta, sino la red vial real (carreteras que pueden estar bloqueadas).

Plataforma Datos Disponibles Uso en el QAP
OpenStreetMap (OSM)
openstreetmap.org		 Mapeo global de carreteras, caminos rurales y topografía. Base para trazar las rutas entre zonas de riesgo.
Openrouteservice
openrouteservice.org		 API de cálculo de matrices de tiempo/distancia usando datos de OSM. Generar la matriz Djl en minutos u horas de viaje entre albergues/zonas.

2.4. Datos Humanitarios y de Salud

Plataforma Datos Disponibles Uso en el QAP
HDX (OCHA ONU)
data.humdata.org		 Datasets estandarizados de Perú, accesibilidad a servicios de salud, datos de carreteras ya limpios. Fuente directa (CSV/JSON) lista para usar en Python sin necesidad de scraping.
INEI / SUSALUD
datosabiertos.gob.pe		 Cantidad de centros de salud (IPRESS), brigadas médicas, población vulnerable. Definir cuántas "Brigadas" (i, k) de cada tipo son necesarias enviar.

3. Estrategia de Construcción de Matrices

Paso 1: Definir el N (Etapa 1: N=3 o N=4)

Para el Día 1, se seleccionan 3 zonas altamente críticas según SENAMHI. Por ejemplo:

  • Zona 1: Piura (Inundaciones severas).
  • Zona 2: Tumbes (Desborde de ríos).
  • Zona 3: Chosica / Lima Este (Huaicos).

Paso 2: Construir la Matriz de Distancia (\(D_{jl}\))

Usando la API de Openrouteservice o consultando OSM, se calcula el tiempo de viaje vehicular entre estas zonas:

Distancia (Horas) Piura Tumbes Chosica
Piura 0 3.5 14.0
Tumbes 3.5 0 16.5
Chosica 14.0 16.5 0

Simulación de El Niño: Si hay un reporte de carretera bloqueada, el valor \(D_{jl}\) se multiplica por un factor de penalización (ej. \(x2\) en tiempo), reflejando la realidad operativa.

Paso 3: Construir la Matriz de Flujo (\(F_{ik}\))

Se definen las brigadas a asignar (Elementos \(i, k\)). Por ejemplo: Brigada Médica, Brigada Logística de Alimentos, Brigada de Rescate.

El flujo se define por la necesidad de coordinación entre ellas. Una brigada médica y una de rescate deben estar en la misma zona o en zonas cercanas (alto flujo).

Flujo (Sinergia) Médica Logística Rescate
Médica 0 5 9
Logística 5 0 3
Rescate 9 3 0

4. Justificación para la Rúbrica

Para obtener el máximo puntaje en el criterio de "Modelo matemático, lectura de datos y factibilidad" (25 puntos), el equipo debe presentar lo siguiente:

  • Fuente de Datos: Mencionar que las distancias \(D_{jl}\) no son inventadas, sino calculadas mediante el enrutamiento de OpenStreetMap y validando el riesgo con SENAMHI.
  • Justificación del Flujo \(F_{ik}\): Explicar que los pesos de flujo se basaron en la matriz de necesidades operativas de INDECI (ej. si una zona reporta damnificados, requiere alta sinergia entre la brigada médica y la logística).
  • Límite Cuántico: Recordar que para \(N=3\) o \(N=4\), el problema se resuelve con Qiskit en simulación local, pero para el Día 2 (\(N \ge 10\)) se usará la API de HDX (OCHA) para extraer los datos de 10 zonas reales y aplicar estrategias de descomposición (híbridas).
